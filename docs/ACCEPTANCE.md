# Проверка перед сдачей

Источник требований — выданное команде ТЗ «Beeline Tariff Marketing Campaigns Case».
Технические проверки подтверждаются файлами в `reports/`, изменения команды — ссылками на объединённые PR.
Личное понимание, использование устройств и приём проекта организаторами вынесены отдельно: репозиторий сам по себе их не подтверждает.

## Обязательный минимум

- [x] Есть исходный пакет организаторов. `python tools/check_package.py` завершается с кодом 0.
- [x] Есть `agent.py` с `Agent.act(env)`.
- [x] `python local_eval.py` завершается без ошибки.
- [x] В результате 1–10 корректных кампаний, нет сообщений «Кампания … отброшена».
- [x] Проведён хотя бы один пилот через `env.run_pilot`; его результат влияет на выбор.
- [x] Соблюдены 100 000 у.е. бюджета и 15 000 контактов с учётом пилотов.
- [x] На кампанию приходится не больше 5 000 засчитываемых абонентов.
- [x] Не больше 20 пилотов, каждый на 10–200 абонентах.
- [x] Агент укладывается в 10 минут.
- [x] `python make_submission.py` создаёт `submission.csv`.
- [x] Используемые NumPy и pandas перечислены в `requirements.txt`; проверенное окружение зафиксировано в `requirements-lock.txt`.

## Качество и воспроизводимость

- [x] `python local_eval.py --runs 10`: сохранены результаты всех прогонов, а не только лучший.
- [x] Зафиксированы средний и минимальный результат, число неудачных прогонов и время.
- [x] Все 20 тестов прошли: 5 проверок агента, 12 проверок аудита, 3 независимых стресс-теста. Вывод: [reports/tests.txt](../reports/tests.txt).
- [x] Проверены отрицательные и противоречивые пилоты, частичный сбой пилотного API, нулевой денежный бюджет и недоступность дорогих каналов.
- [x] Аудит проверяет пустые аудитории, границу 5000, повторные контакты и превышение остатков бюджета/контактов после пилотов.
- [x] Нет повторного сложения выручки одних и тех же абонентов.
- [x] Стратегия использует результаты текущих пилотов и не подогнана под секреты мок-среды.
- Не применяется: обработка отказов LLM и хранение API-ключа — LLM и внешние API не используются.
- [x] README описывает реализованные возможности и воспроизводимые результаты.
- [x] [PR #2](https://github.com/BAITC-Hacks/hack-acbb98e4-she/pull/2) (`704aa9c`, стресс-тесты) и [PR #3](https://github.com/BAITC-Hacks/hack-acbb98e4-she/pull/3) (`42c1665`, остатки ресурсов в отчётах) объединены в `main`.

## Подтверждают участники и организаторы

- [ ] Участники подтверждают личный вклад, работу со своих устройств и понимание своих изменений. PR подтверждают изменения, но не удостоверяют эти обстоятельства.
- [ ] Приём проекта по процедуре организаторов подтверждён командой.

Неотмеченные пункты выше не означают, что требуется написать дополнительный код.
Артефакты находятся в репозитории; способ передачи и подтверждение приёма в выданном ТЗ не описаны.

## Критерии жюри

| Критерий | Баллы | Чем подтверждаем |
| --- | ---: | --- |
| Соответствие задаче и работоспособность | 25 | Официальный локальный прогон, корректный submission.csv |
| Техническая реализация | 25 | Код агента, адаптивные пилоты, проверки ограничений |
| README и воспроизводимость | 25 | Установка с чистого окружения, команды проверки, фактические ограничения |
| Ценность и применимость | 15 | Чистый результат с учётом затрат и понятный план кампаний |
| Потенциал и оригинальность | 10 | Обоснованные решения по неопределённости и дальнейшему развитию |

Результаты локальной мок-среды не предсказывают конкурсный балл. Все данные кейса
синтетические; выводы не описывают реальные показатели Beeline.
